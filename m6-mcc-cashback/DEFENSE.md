1. **Рамка (10 с).** «Учебный кейс: банк с картой кэшбэка, синтетические данные. Программа на 19 % дороже бюджета, клиенты жалуются на неначисления».
2. **Что сделал (25 с).** «Формализовал девять правил — от исключённых MCC до возвратов — и вынес ставку в таблицу решений DMN, которую проверяют автотесты. Сгенерировал на pandas и Faker 109 тысяч операций с заложенными особенностями: “умные” клиенты, кафе с MCC супермаркета, возвраты. Посчитал на SQL с оконной функцией для лимита».
3. **Что нашёл (15 с).** «62 % расходов — супермаркеты и АЗС. Клиенты, которые выбирают категории под свои траты, стоят на 43 % дороже. Сценарий “АЗС 3 % и без повышенных супермаркетов” даёт минус 10 % к бюджету».
4. **Жалобы (10 с).** «Жалобы в основном объяснимы: исключённые MCC, покупки до 100 рублей, лимит. Отдельно — кафе в гипермаркетах с кодом супермаркета: это не ошибка расчёта, MCC ставит эквайер».

## 3. Вопросы, которые зададут, и тезисы ответов
| # | Вопрос | Тезисы ответа |
|---|---|---|
| 1 | Что такое MCC и кто его присваивает? | Четырёхзначный код вида деятельности магазина. Присваивает банк-эквайер при подключении терминала, по правилам платёжной системы. Мы как эмитент только видим его в операции. Поэтому «кафе с кодом 5411» мы не можем исправить — только завести исключение по ID магазина |
| 2 | Как обработать возврат покупки с кэшбэком? | CB-07: списываем ровно тот кэшбэк, что начислили за эту покупку (связь `original_tx_id`), в месяце возврата. Если в этом месяце начислений не хватает — переносим долг (CB-08), карта в минус не уходит. В данных 327 возвратов пришлись на следующий месяц |
| 3 | Почему данные синтетические? | Реальные операции — банковская тайна и персональные данные (152-ФЗ), в публичный репозиторий их нельзя. Синтетика с фиксированным seed воспроизводима, и в неё можно заложить нужные случаи: возвраты через границу месяца, «чужой» MCC, покупки до 100 ₽ |
| 4 | Почему лимит не в DMN? | DMN решает по одной операции. Лимиту нужна сумма уже начисленного за месяц — это агрегат, его считаю оконной функцией `SUM() OVER (PARTITION BY client_id, month ORDER BY tx_date)` |
| 5 | Почему у первой таблицы hit policy UNIQUE, а у второй FIRST? | MCC входит ровно в одну группу — два совпадения были бы ошибкой справочника, UNIQUE её поймает. Во второй правила перекрываются (исключённый MCC и покупка до 100 ₽), и важен порядок: CB-01 главнее |
| 6 | Почему программа дороже бюджета? | Две причины в данных: «умный» выбор категорий (клиенты берут то, где тратят больше всего — эффективная ставка 1,71 % против 1,20 %) и щедрые 5 % на АЗС при больших чеках (3,33 % оборота АЗС уходит в кэшбэк) |
| 7 | Как бы вы выбирали сценарий? | Посчитал стоимость пяти сценариев на тех же операциях. Но цифра — только половина: снижение ставки может увести клиентов. Поэтому сначала A/B-тест на части новых клиентов, метрики — стоимость, оборот на клиента, отток |
| 8 | Как проверить, что DMN и SQL считают одинаково? | Справочник MCC — общий источник: тест сверяет каждый MCC из `mcc_groups.csv` с результатом DMN. Следующий шаг — сверить ставки по выборке операций из базы (CR-3) |

**«Что будет, если…»**
- *Магазин сменил MCC посреди месяца* → берём MCC из операции, не из справочника магазинов.
- *Клиент не выбрал категории* → всё по 1 %, правило CB-04.
- *Частичный возврат* → открытый вопрос продукту; предлагаю пропорционально сумме.

## 7. Глоссарий
| Термин | Своими словами |
|---|---|
| Кэшбэк | Часть суммы покупки, которую банк возвращает клиенту |
| MCC | Код категории магазина, по нему банк понимает, что за покупка |
| Эмитент | Банк, который выпустил карту клиенту (это мы) |
| Эквайер | Банк, который обслуживает терминал магазина; он присваивает MCC |
| Интерчейндж | Комиссия, которую эквайер платит эмитенту с каждой покупки; из неё обычно и платят кэшбэк |
| Повышенная категория | Категория с повышенной ставкой, которую клиент выбирает на месяц |
| Лимит кэшбэка | Максимум, который клиент может получить за месяц |
| Квази-кэш | Операции, похожие на снятие наличных: пополнение кошельков, покупка фишек, лотерей |
| Эффективная ставка | Сколько процентов оборота реально ушло в кэшбэк после всех правил |
| DMN | Таблица решений «если… то…», понятная и бизнесу, и системе |
| Hit policy | Что делать, если подошло несколько строк DMN: FIRST — первая, UNIQUE — ошибка |
| Синтетические данные | Сгенерированные данные, похожие на настоящие, без реальных людей |
| Faker | Библиотека Python, которая генерирует правдоподобные имена, города, компании |
| Seed | Начальное число генератора случайностей: тот же seed — те же данные |
